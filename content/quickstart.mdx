To publish an app, put a `Dockerfile` and `zenith-compose.yml` at the root of a public GitHub repository. Zenith can build your app image before submission, or you can supply a public image.

<Visibility for="humans">

<Card title="Let an agent prepare the repository" icon="wand-magic-sparkles" href="/content/agent-skill" cta="Install the Zenith skill" arrow="true">
  The Zenith skill can prepare the container image and `zenith-compose.yml` pull requests for you.
</Card>

Follow these steps in order.

<Steps>
  <Step title="Containerise your app">
    Prepare a root `Dockerfile`. Choose whether Zenith builds your app image or you use a public image. Any other services need public images.

    [Prepare your container images](/content/containerise)
  </Step>
  <Step title="Create zenith-compose.yml">
    Add the services, public endpoints, environment values, and persistent storage that your app needs.

    [Create the manifest](/content/zenith-compose)
  </Step>
  <Step title="Submit your app">
    Connect the repository to Zenith, build the marketplace listing, and send the app for review.

    [Submit the repository](/content/submit)
  </Step>
</Steps>

</Visibility>

<Visibility for="agents">

> Agent workflow
>
> Prepare a repository for Zenith in this order:
>
> 1. Prepare a root `Dockerfile`. Use a public `image` for each service, or `build: .` for one app service that Zenith will build before submission.
> 2. Create or validate the root `zenith-compose.yml` using the [manifest guide](/content/zenith-compose) and [complete reference](/content/zenith-compose-reference).
> 3. Run the local Compose checks documented on those pages.
> 4. Stop before account connection, publication consent, or final submission. Those actions require the repository owner in the [publishing dashboard](/content/submit).
>
> Preserve existing application behavior. Do not add `internal.yml`, pricing, Kubernetes placement, or any other operator-only field to the developer repository.

</Visibility>

## Before you start

<Info>
You need all of the following before you begin:

- A public GitHub repository that you own or administer.
- Permission to publish and maintain the app.
- Docker installed for local builds and tests.
</Info>
