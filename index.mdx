Use the [Zenith CLI](https://github.com/zenith-hosting/zenith-cli) to take your app from a local project to a tested deployment and a marketplace submission.

```bash
npm install -g @zenith-hosting/cli
zenith auth login
zenith init
zenith check --upload-size
zenith up
```

Run these commands from your app's root directory with Node.js `20.10` or later. `zenith up` builds your local project on Zenith and returns a temporary URL. When you are ready to submit a public GitHub commit for review, use `zenith publish`.

## Agent workflow

> 1. Read the [CLI quickstart](/content/quickstart), [container guide](/content/containerise), and [Compose guide](/content/zenith-compose). Use the [reference](/content/zenith-compose-reference) for schema details.
> 2. Use `NO_COLOR=1` for plain output in a non-interactive session. Run without a TTY and supply explicit inputs, such as `--template` for `init` and `--metadata` for publishing. See [agent session setup](/content/quickstart#run-a-non-interactive-agent-session).
> 3. Run `NO_COLOR=1 zenith check --upload-size`. When a remote test is authorized, run `NO_COLOR=1 zenith up` and verify the app at the returned URL. Follow the [testing workflow](/content/up).
> 4. Record the session ID, tested commit, local changes, verification results, and expiry. Stop the preview with `NO_COLOR=1 zenith down` when done.
> 5. Only when explicitly authorized, follow the [publishing workflow](/content/publish) to submit a pushed public commit. Record the submission receipt and status.
>
> `NO_COLOR=1` does not bypass prompts, browser OAuth, GitHub connection, or the Developer Agreement. Do not push commits, publish images, change registry visibility, or submit an app without authorization. A preview is temporary; a publish submission enters review, not immediate marketplace publication.
